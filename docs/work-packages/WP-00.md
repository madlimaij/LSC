# WP-00 — Real-language inputs (human task)

- **Owner:** project owner
- **Needed before:** Gate G4 / Wave 5
- **Kept:** outside the repository, at the path given by `LSC_REAL_INPUTS`

## Goal

Provide the evidence the compiler needs for the real custom language. The compiler can only be as good as these inputs.

## Checklist

- [ ] One Skill file per construct type needed (§5.3 of the plan): module declaration, procedure/function definition (including how it ends), call, include/import, database read, database write, configuration/feature-flag reference, entry point
- [ ] Per construct: at least 5 positive examples, with the expected captures written down
- [ ] Per construct: at least 2 negative examples, especially traps: the keyword inside a comment, inside a string, as part of a longer identifier, a look-alike construct
- [ ] Comment syntax, string syntax and case sensitivity stated
- [ ] Known multi-line forms stated (statements continued over several lines, nested blocks)
- [ ] File extensions and directory conventions
- [ ] Repository sample: 20–50 representative files, never sent to a model
- [ ] Written confirmation of which model provider is allowed for these snippets
