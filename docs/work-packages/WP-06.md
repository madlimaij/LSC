# WP-06 — Skill ingestion

- **Owner:** `skill-ingester`
- **Depends on:** WP-03
- **Owns:** `src/ingest/`, `src/cli/commands/ingest.ts`

## Goal

Turn a folder of Skill Markdown files into constructs with their prose and examples, preserving exact provenance.

## Deliverables

- Markdown parsing with `unified` + `remark-parse` (not regex over Markdown)
- `Construct = { id, ruleTypeHint?, skillPath, anchor, prose, examples: Example[] }`; anchors are stable heading slugs (`language-basics.md#procedures`)
- Inline example extraction using the info-string format in plan §6.1, with the following `yaml expect` block; output is the `Example` record from WP-03
- Merge with sidecar examples and `reviews.yaml` (via the WP-03 loaders) by construct id
- SHA-256 hash per Skill file, for `sourceSkills`
- Diagnostics instead of crashes: example without construct, expect block without example, duplicate example id, construct without any positive example
- Bounded prose extraction: the Skill section for a construct is capped (configurable character limit) with a truncation marker, because it is what WP-09 sends to the model
- CLI: `lsc ingest <skills-dir>` printing constructs, example counts per polarity, and diagnostics

## Acceptance criteria

- All toylang Skill files ingest with zero errors and the expected example counts (asserted in tests)
- Each diagnostic has a test fixture that triggers it
- Changing one character in a Skill file changes its hash and nothing else
