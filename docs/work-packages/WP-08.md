# WP-08 — Model provider layer

- **Owner:** `llm-integrator`
- **Depends on:** WP-02
- **Owns:** `src/llm/`, `fixtures/recordings/`

## Goal

A provider-neutral way to ask a model for structured output, with hard budgets and a full log of what was sent.

## Deliverables

- `LlmProvider` interface: `complete({ system, messages, maxOutputTokens }) → { text, usage }`
- `AnthropicProvider` using `@anthropic-ai/sdk`; model name, API key and base URL from configuration, never hard-coded
- `FakeProvider` replaying recordings from `fixtures/recordings/` keyed by a hash of the request, failing loudly on an unknown request (D7)
- Recording mode: run with a real provider once, save request/response pairs (toylang only)
- `structured(provider, zodSchema, request)`: extract JSON from the response, validate with Zod, return typed result or a typed error; no silent fallback
- Budgets: per-call output cap, per-compile total token cap, stop with a clear error when exceeded
- Snippet log: JSONL file per compile run (`.lsc/logs/<run-id>.jsonl`) with timestamp, provider, model, full request text, token usage
- Configuration file `lsc.config.json` (validated with Zod) for provider, model, budgets, log location

## Acceptance criteria

- All tests use `FakeProvider`; a test fails if the Anthropic client is constructed during `npm test`
- Budget exhaustion and invalid JSON each have a test
- Every request in a test run appears in the snippet log

## Notes

- Keep the interface small so an approved or locally hosted model can be added at Gate G4 with one new class.
