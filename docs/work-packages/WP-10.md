# WP-10 — Versioning, recompile and export

- **Owner:** `contract-architect`
- **Depends on:** WP-07, WP-09
- **Owns:** `src/release/`, `src/cli/commands/export.ts`

## Goal

Every compile produces a correctly versioned Rule Set that Navigator can adopt safely, and a Skill change leads to a new version.

## Deliverables

- Diff between previous and new Rule Set: rules added, removed, renamed, pattern changed, capture roles changed
- Version assignment following plan §5.1 from that diff; first export is `1.0.0`
- Unchanged Skill files (same hash) reuse previous rules without a model call, unless `--force`; changed Skill files re-synthesise only their constructs
- `lsc export <draft-ruleset> --out <file> [--previous <file>]` writing only `validated` rules plus a `CHANGELOG` entry generated from the diff
- `lsc compile` calls export at the end when `--export` is given

## Acceptance criteria

- Changing one toylang Skill file and recompiling (via recordings) produces a new version, re-synthesises only that construct, and the changelog names the change
- Removing a construct produces a major bump; adding one produces a minor bump; a pattern-only change produces a patch bump (each tested)
- An exported Rule Set passes `lsc validate-ruleset` and `lsc test` offline
