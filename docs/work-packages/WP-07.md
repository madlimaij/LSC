# WP-07 — Validation report and review CLI

- **Owner:** `report-builder`
- **Depends on:** WP-05
- **Owns:** `src/report/`, `src/cli/commands/report.ts`, `src/cli/commands/review.ts`

## Goal

Let a person decide whether a Rule Set is trustworthy without reading compiler internals (specification §5).

## Deliverables

- `lsc report <results.json> [--format md|html|json]`
- Report sections, in this order:
  - Overall verdict line: rules validated / low confidence / rejected; example pass rate; constructs without a usable rule
  - Coverage table: rule type × status × confidence
  - Per rule: pattern, captures, confidence with the reason (which threshold was missed), pass rate, representative matches, missed examples with expected vs actual, wrong captures, false positives from negative examples
  - Unreviewed sample matches, grouped per rule, with snippets and file:line locations
  - Provenance: Skill file and anchor per rule; Skill file hashes
- HTML output is a single self-contained file (no external assets), readable offline
- `lsc review <results.json>`: interactive terminal flow stepping through unreviewed sample matches; verdict `correct` / `false positive` / `skip`; writes entries to `reviews.yaml` in the WP-03 format (D9)

## Acceptance criteria

- Report on toylang fixture results shows every section; snapshot-tested for Markdown
- A broken Rule Set (from WP-05's test) produces a report where each defect is visible in the per-rule section
- A review session's verdicts load back through the WP-03 loader as valid examples
- Confidence is never shown without its reason
